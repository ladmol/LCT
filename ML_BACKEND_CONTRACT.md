# Контракт ML ↔ backend для Vehicle Re-ID

Версия основного признака: `vehicle-reid-ensemble-256-v1`.

## Вход

Один запрос содержит:

- JPEG/PNG полного кадра в байтах;
- `event_id`, `camera_id`, `captured_at`;
- массив объектов `detection_id` и `bbox_xywh = [x, y, width, height]`;
- координаты в пикселях исходного кадра до resize.

```json
{
  "event_id": "event-42",
  "camera_id": "cam-7",
  "captured_at": "2026-09-27T12:00:00+03:00",
  "detections": [
    {"detection_id": "det-1", "bbox_xywh": [120, 80, 640, 360]}
  ]
}
```

Backend не вырезает и не масштабирует автомобиль. Он передаёт один полный кадр
и все BBox этого кадра одним вызовом.

## Выход ML

Для каждого корректного BBox возвращаются:

- тот же `detection_id`;
- `model_version = vehicle-reid-ensemble-256-v1`;
- `embedding_dim = 2816`;
- `embedding`: ровно 2816 значений `float32`;
- `embedding_norm`: около 1, допустимое отклонение `1e-4`.

```json
{
  "model_version": "vehicle-reid-ensemble-256-v1",
  "embedding_dim": 2816,
  "detections": [
    {
      "detection_id": "det-1",
      "embedding": [0.0123, -0.0041],
      "embedding_norm": 1.0
    }
  ]
}
```

В примере массив сокращён. Для HTTP предпочтителен бинарный `float32` или
base64, если JSON из 2816 чисел создаёт лишнюю нагрузку.

## Вызов Python

```python
from reid.infer import VehicleEnsembleEmbedder

embedder = VehicleEnsembleEmbedder(
    "ml/weights/convnext_tiny_256_fp16.pt",
    "ml/weights/resnet50_256_fp16.pt",
    first_weight=0.5,
    tta_flip=True,
)

vectors = embedder.embed_many(image_bytes, bboxes_xywh)
# shape (N, 2816), dtype numpy.float32
```

Обе модели загружаются один раз при старте процесса. `embed_many` сохраняет
порядок входных BBox.

## Препроцессинг и цифровой признак

ML выполняет crop по BBox, дополнение до квадрата без искажения пропорций,
resize 256×256 и ImageNet-нормировку. Для оригинального и отражённого кропа
усредняются признаки ConvNeXt Tiny и ResNet50. Итоговый вектор:

```text
[sqrt(0.5) × convnext_vector_768, sqrt(0.5) × resnet_vector_2048]
```

Обе части L2-нормированы. Поэтому весь вектор также имеет норму 1, а его
скалярное произведение равно среднему cosine двух моделей.

## Хранение и версия

Рядом с каждым вектором backend хранит:

- `model_version`, `embedding_dim`;
- `event_id`, `detection_id`, `camera_id`, `captured_at`;
- исходный `bbox_xywh`;
- ссылку на кадр или кроп в принятом хранилище.

Векторы разных `model_version` сравнивать нельзя. При смене модели активная
gallery полностью переиндексируется до переключения поискового трафика.

## Поиск и отказ

Так как векторы нормированы:

```text
cosine_similarity = query_embedding · gallery_embedding
```

- сортировка по убыванию cosine;
- `top_k = 10`;
- стартовый порог принятия `0.5051871538`;
- порог хранится в конфигурации backend;
- score для UI может быть `(cosine + 1) / 2`, но это не вероятность;
- ниже порога пользовательский список совпадений пуст, а технический top-10
  можно сохранить для диагностики.

Порог выбран на dev. На локальном holdout он дал F1 `0.4505` и TNR `0.7241`.
Перед промышленным включением его следует перекалибровать на целевых камерах.

## Быстрый режим

При жёстком требовании к задержке допускается отдельная версия
`vehicle-reid-convnext-256-v1`: один ConvNeXt без flip TTA, размерность 768,
порог `0.3886348009`. Она работает около 63 объектов/с на RTX 3060 против
27,5 объектов/с у ансамбля. Индексы двух режимов изолированы.

## Ошибки

- `400 INVALID_IMAGE`: изображение не декодируется;
- `400 INVALID_BBOX`: BBox имеет неположительную площадь или полностью вне кадра;
- `413 IMAGE_TOO_LARGE`: превышен лимит кадра;
- `422 EMPTY_DETECTIONS`: массив автомобилей пуст;
- `503 MODEL_UNAVAILABLE`: checkpoint не загружен;
- `500 INFERENCE_FAILED`: внутренняя ошибка с `request_id`.

Стратегия частичных ошибок должна быть общей для всех клиентов: либо атомарный
отказ запроса, либо ошибка на конкретном элементе с сохранением соответствия
остальных `detection_id`.

## Нефункциональные требования

- checkpoint загружаются при старте, инференс не обращается в интернет;
- несколько BBox одного кадра обрабатываются батчем;
- ориентир RTX 3060, batch 16: 27,5 объекта/с, пик CUDA 444 МБ;
- backend ограничивает размер кадра и число BBox, задаёт таймаут;
- в логах нет байтов изображения и полного embedding;
- в логах есть версия, длительность, размер батча, event/request ID и ошибка.

## Приёмочные проверки

1. Один корректный BBox возвращает `(2816,)`, `float32`, норма около 1.
2. N BBox возвращают `(N, 2816)` в исходном порядке `detection_id`.
3. Повторный вызов с тем же входом воспроизводим в пределах численной погрешности.
4. Поиск сравнивает только одинаковые `model_version` и отдаёт не более 10 строк.
5. Нулевая площадь и полностью внешний BBox дают `INVALID_BBOX`.
6. При смене версии старый индекс не обслуживает новый запрос.
7. Тестовый экспорт содержит 1110 query, 750 gallery и размерность 2816;
   валидатор ML завершается без ошибок.

Марка, модель и рестайлинг пока экспериментальны и не входят в обязательный
контракт. Номерные знаки не используются моделью и не входят в API.
