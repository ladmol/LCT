# ML: поиск одного автомобиля на кадрах разных камер

Этот каталог содержит нашу часть решения конкурса: обучение модели Vehicle Re-ID,
проверку качества, извлечение эмбеддинга и создание файлов сдачи. **Сервис получает
готовый BBox** `(x, y, w, h)` в пикселях исходного кадра. Детектор, OCR и трекинг
не участвуют в конкурсном пути. OCR и отдельный признак номерного знака не
используются.

## Текущее состояние

Основной checkpoint сейчас — ResNet50 `outputs/resnet50_256/best.pt` (12 эпох,
256×256, RTX 3060, около 98 МиБ). На одном фиксированном разделении по
автомобилям он улучшил качество относительно предыдущих вариантов:

| Модель | Dev mAP / Rank-1 | Holdout mAP / Rank-1 | Holdout F1 кандидата / TNR |
| --- | --- | --- | --- |
| ResNet18 | 0,290 / 0,179 | 0,309 / 0,178 | 0,175 / 0,397 |
| ResNet18 после внешнего пилота | 0,280 / 0,169 | 0,308 / 0,186 | 0,185 / 0,431 |
| ResNet50 192×192 | 0,344 / 0,226 | 0,387 / 0,271 | 0,273 / 0,259 |
| ResNet50 256×256 | **0,404 / 0,284** | **0,429 / 0,308** | **0,307** / 0,259 |

F1 и доля правильных отказов (TNR) обычно конфликтуют при одном пороге. Порог
0,583, выбранный по максимуму dev F1, даёт значения в таблице. Для новой модели
сбалансированный порог 0,656 дал на holdout F1 0,308 и TNR 0,672: F1 сохранился,
а отказ стал заметно надёжнее. Рабочую точку можно выбрать при экспорте без
переобучения. Созданы и проверены варианты `outputs/submission_resnet50_256/`
и `outputs/submission_resnet50_256_balanced/` для
1 110 запросов и 750 изображений галереи. При одинаковом размере батча их
векторы и топ-10 побайтно совпадают; различается только `candidates.csv`.
Это локальная проверка, а не оценка на скрытом тесте организаторов.

Пилот Auto.ru содержит 52 raw снимка из 13 объявлений Camry, Rio и Solaris.
Для них созданы обзорные листы в `outputs/auto_ru_review/`. Из них вручную
проверены и подготовлены 26 кропов восьми автомобилей; номера и дилерские
таблички закрыты. Остальные raw снимки в обучение не допускаются. Пилот слишком
мал, чтобы судить о пользе внешних данных без сравнения на holdout.
После дообучения на конкурсном train пилот дал на holdout mAP 0,308 против
0,309 у обычного ResNet18: доказанного выигрыша от этих 26 фото нет.

На RTX 3060 замер полного пути «JPEG из ZIP → BBox → вектор» для 256 запросов
дал около 55 изображений/с у ResNet50 256×256 при батче 16 и 49 изображений/с
по одному. Предыдущая ResNet50 192×192 давала около 68 изображений/с. Это
локальный замер, а не гарантированная задержка backend.

## Что происходит с изображением

```text
JPEG + BBox xywh
  → вырезать автомобиль из полного кадра
  → сохранить пропорции и дополнить до квадрата
  → размер 256×256 и нормировка ImageNet
  → ResNet50 → 2048 чисел float32 → L2-нормировка
  → косинусное сходство с векторами галереи
  → топ-10 и отдельное решение о пороге отказа
```

Фотографии **одного** автомобиля должны давать близкие векторы, даже если ракурс
и камера изменились. Во время обучения используются метки `vehicle_id` и две
потери: классификация обучающих экземпляров и triplet loss, которая сближает
разные виды одного экземпляра. Классификатор нужен только для обучения; при
поиске используются векторы, так что новые автомобили допускаются без
переобучения списка классов.

Цифровой признак получается из последнего слоя ResNet после усреднения
пространственных карт признаков: 512 чисел у ResNet18 или 2048 у ResNet50.
Затем вектор делится на свою L2-норму. Поэтому косинусное сходство двух
машин считается обычным скалярным произведением их векторов. Числа не
являются отдельными понятными человеку полями «царапина» или «фара»:
сеть сама учится полезным сочетаниям деталей по меткам экземпляров. При
замене backbone размерность и значения меняются, поэтому галерею нужно
пересчитать тем же checkpoint.

## Конкурсные данные и проверка

Поместить исходный архив в `ml/data/dataset.zip`. Распаковывать 7 ГБ не нужно.
В текущем архиве: 9 556 строк `train.csv` для 1 541 автомобиля, 1 110 строк
`test_query.csv`, 750 строк `test_gallery.csv`. Каждый `image_id` указывает на
`images/<image_id>.jpg`. Координаты заданы как левый верхний угол, ширина и
высота. `camera_id` есть **только в train.csv**, хотя описание архива говорит
иначе. На тесте мы его не используем.

При фиксированном `seed=42` `reid/protocol.py` выделяет 70% `vehicle_id` на
обучение, 15% на подбор эпохи/порога и 15% на итоговую локальную проверку.
Идентичности не пересекаются. В проверке для известных машин галерея берётся
с одной камеры, а запросы — с других; четверть идентичностей исключена из
галереи и имитирует запрос без совпадения. Порог выбирается на dev и затем
проверяется на holdout. Файл `outputs/baseline/split.json` сохраняет состав
разделения. ResNet50 оценён на том же разделении. Это **локальный** протокол; скрытая оценка организаторов может
иметь другое распределение запросов и камер.

`mAP`/Rank-1/Rank-5 измеряют ранжирование только известных машин. Для режима
предложения кандидата `F1` означает корректное принятие топ-1; ошибочно
принятые запросы считаются ложными срабатываниями. `TNR` — доля правильных
отказов среди запросов без совпадения. `confidence` в CSV — преобразованное
косинусное сходство `(cosine + 1) / 2`, **не вероятность**. Сам порог хранится
в сырой шкале косинуса внутри checkpoint.

## Установка и запуск

Поддерживается Python 3.11–3.13; проверено на 3.13. Для обучения желательна NVIDIA GPU. Команды выполняются
из каталога `ml/`. Зависимости описаны в `pyproject.toml` и `uv.lock`.

```powershell
uv sync --locked --cache-dir .uv-cache --no-managed-python
uv run python -m scripts.prepare_weights --arch resnet50
uv run python -m reid.train --archive data/dataset.zip --output outputs/resnet50_256 --arch resnet50 --init-weights data/weights/resnet50_imagenet.pth --epochs 12 --image-size 256 --eval-batch-size 16
uv run python -m scripts.make_submission --archive data/dataset.zip --checkpoint outputs/resnet50_256/best.pt --output outputs/submission_resnet50_256
uv run python -m scripts.validate_submission --archive data/dataset.zip --output outputs/submission_resnet50_256
uv run python -m pytest -q tests/test_pipeline.py
```

`prepare_weights` скачает официальные ImageNet веса torchvision при первом
запуске; дальше файл `data/weights/resnet50_imagenet.pth` хранится локально.
Готовый `best.pt` содержит веса модели и подобранный порог; **инференс с ним
не обращается в сеть**. Веса ResNet50: `torchvision.models.ResNet50_Weights.IMAGENET1K_V2`.

Если обучение прервалось после сохранения `best.pt`, можно продолжить:

```powershell
uv run python -m reid.train --archive data/dataset.zip --output outputs/resnet50_256 --resume outputs/resnet50_256/best.pt --epochs 8 --image-size 256 --eval-batch-size 16
```

Число `--epochs` при продолжении означает **дополнительные** эпохи. Скрипт
загружает веса лучшей эпохи, но создаёт новый оптимизатор; это дополнительное
дообучение, а не точное возобновление состояния обучения. Скрипт печатает mAP
каждой эпохи, выбирает лучшую и пишет `report.json`. Для быстрой
проверки кода есть `--epochs 1 --max-steps 2 --image-size 128`; такой
checkpoint нельзя выдавать за обученную модель. RTX 3060 с 12 ГБ уже
использовалась с `--image-size 256`, 4 идентичностями × 4 снимками в батче и
автоматической смешанной точностью. При нехватке памяти можно уменьшить
`--identities-per-batch` до 2, сохраняя минимум 2 снимка на экземпляр.

Для повторения замера скорости и анализа порога:

```powershell
uv run python -m scripts.benchmark_reid --checkpoint outputs/resnet50_256/best.pt --samples 256 --batch-size 16
uv run python -m scripts.analyze_refusal --checkpoint outputs/resnet50_256/best.pt --batch-size 16 --output outputs/resnet50_256/refusal_comparison.json
```

### Разбор ошибок

```powershell
uv run python -m scripts.analyze_errors --checkpoint outputs/resnet50_256/best.pt --output outputs/error_analysis_resnet50_256 --split holdout --batch-size 16
```

Скрипт создаёт `queries.csv`, `report.json` и `confident_mistakes.jpg`. Для
ResNet50 256×256 на holdout поместила правильную машину в топ-10 у 66,8%
известных запросов; 207 запросов остались за пределами топ-10. У 192×192 было
61,3% и 241 промах. Самый слабый срез — BBox с отношением ширины к высоте
больше 2: медианный ранг улучшился с 22 до 15, но Rank-1 остался около 0,03
против 0,317 у обычных BBox.
На визуальном листе среди ошибок часто встречаются боковые ракурсы, темнота,
засветка, перекрытия и очень похожие автомобили. Следующий эксперимент должен
адресовать ракурс и сильное вытягивание BBox, а не просто повышать разрешение.

### Файлы сдачи

`make_submission.py` создаёт:

- `submission.csv`: ровно десять ID галереи для каждого запроса, в порядке убывания сходства;
- `embeddings.npy`: сначала векторы всех строк `test_query.csv`, затем всех строк `test_gallery.csv`, строго в порядке CSV;
- `candidates.csv`: принятые кандидаты с численным score; для отказа строка с пустыми `gallery_id` и `confidence`.

Чтобы использовать более осторожный порог для `candidates.csv`, передайте
`--refusal-threshold 0.6555828452` в `make_submission.py`. `submission.csv` и
`embeddings.npy` от этого не меняются. Это порог из локального dev;
его пригодность для скрытого теста неизвестна.

```powershell
uv run python -m scripts.make_submission --archive data/dataset.zip --checkpoint outputs/resnet50_256/best.pt --output outputs/submission_resnet50_256_balanced --refusal-threshold 0.6555828452
uv run python -m scripts.validate_submission --archive data/dataset.zip --output outputs/submission_resnet50_256_balanced
```

Формат пустой строки в `candidates.csv` нужно сверить с официальным скриптом
жюри, если он будет опубликован. Все три файла создаются одним checkpoint и
одной функцией препроцессинга.

## Согласование с backend

Публичный интерфейс расположен в `reid/infer.py`:

```python
from reid.infer import VehicleEmbedder

embedder = VehicleEmbedder("outputs/resnet50_256/best.pt")
vector = embedder.embed(image_bytes, (x, y, w, h))
# vector: numpy.float32, форма (2048,), L2-норма около 1
vectors = embedder.embed_many(image_bytes, [(x1, y1, w1, h1), (x2, y2, w2, h2)])
# vectors: numpy.float32, форма (2, 2048)
```

Backend передаёт **один** полный кадр и BBox для каждого размеченного авто.
Для нескольких BBox одного кадра он вызывает `embed_many`. Backend хранит
вектор и метаданные, считает косинусное сходство,
возвращает кандидатов. В ML нет доступа к БД и логики номера. Размерность
вектора и версия checkpoint должны сохраняться рядом с индексом: при смене
модели всю галерею нужно переиндексировать. Текущие маршруты backend пока
используют другую схему входа; её надо согласовать перед интеграцией.

## Дополнительные фотографии Auto.ru

Локальный сборщик `scripts/collect_auto_ru.py` исключён из Git. Он читает
общедоступные страницы, указанные через `--seed-url`, ограничивает число
объявлений и снимков и делает паузу между запросами. Не использует закрытые
API и не обходит ограничения доступа.

```powershell
uv run python -m scripts.collect_auto_ru --seed-url "https://auto.ru/cars/toyota/camry/2020-year/used/" --max-listings 10 --max-images 8 --dry-run
uv run python -m scripts.collect_auto_ru --seed-url "https://auto.ru/cars/toyota/camry/2020-year/used/" --max-listings 10 --max-images 8
```

Фотографии попадают в `data/auto_ru/raw/`, а источник, ID объявления,
марка/модель, название поколения, SHA-256 и статус — в `manifest.jsonl`.
ID объявления — **предварительная** метка экземпляра, требующая проверки:
объявление может содержать фото другой машины или салона. Отсутствие слова
«рестайлинг» помечается `unknown`, а не «дорестайлинг».

Raw фотографии **не подаются в обучение**. Для каждой одобряемой фотографии
создайте запись в `data/auto_ru/reviews.jsonl` с BBox главной машины и всеми
прямоугольниками, которые требуется закрыть (номерные знаки, лица).

```powershell
uv run python -m scripts.build_review_sheets --data data/auto_ru --output outputs/auto_ru_review
```

Обзорные листы помогают отобрать кадры; координаты для `reviews.jsonl` надо
снимать по **исходным** файлам в `raw/`, а не по уменьшенным листам. Пример записи:

```json
{"image_path":"raw/1234567890-abcdef01/00.jpg","status":"approved","vehicle_bbox":[100,200,900,550],"redactions":[[200,500,120,50]],"plate_reviewed":true,"face_reviewed":true}
```

Прямоугольники имеют формат `(x, y, w, h)` в **исходном** фото. Если фото не
подходит, укажите `status: rejected`. При проверке можно исправить `make` и
`model` и добавить `restyling_label`: `pre-restyling`, `restyling` или
`unknown`. Метку «до рестайлинга» ставим только при подтверждении по
поколению/году и внешним признакам, а не по отсутствию слова в объявлении.
После проверки:

```powershell
uv run python -m scripts.process_auto_ru_reviews --data data/auto_ru --reviews data/auto_ru/reviews.jsonl
```

Скрипт создаёт `approved/` и `approved.jsonl` только для явно проверенных
фотографий. Для обучения нужно минимум восемь разных объявлений с двумя
одобренными фото в каждом; для содержательной проверки марки/модели нужны
несколько классов и отдельная проверочная выборка. Как только такой набор
собран, запускаем эксперимент:

```powershell
uv run python -m scripts.eval_external_pilot --data data/auto_ru --checkpoint outputs/baseline/best.pt
```

Этот тест исключает совпадение снимка с самим собой. На 26 одобренных фото
ResNet18 дал Rank-1 0,808 и mAP 0,738, но фотографии одного объявления часто
имеют общий фон. Поэтому результат служит проверкой группировки, а модель
выбираем по конкурсному dev/holdout.

```powershell
uv run python -m reid.pretrain_external --data data/auto_ru --contest-archive data/dataset.zip --output outputs/external_pilot --init-weights data/weights/resnet18_imagenet.pth --arch resnet18 --epochs 20 --eval-every 5 --identities-per-batch 4 --views-per-identity 2 --image-size 192
uv run python -m reid.train --archive data/dataset.zip --init-weights outputs/external_pilot/best.pt --output outputs/from_external_pilot --arch resnet18 --epochs 12 --image-size 192
```

Первый шаг обучает по ID объявления, марке и модели. В батче берутся два разных
автомобиля одной модели как сложные отрицательные примеры, если они есть.
`restyling` обучается только при наличии как минимум двух **явно размеченных**
классов. Отсутствие слова «рестайлинг» в объявлении не превращаем в
отрицательную метку. Второй шаг использует только backbone от внешнего
checkpoint и дообучает его на конкурсных камерах. Сравнение сделано на **том же**
`split.json`: dev mAP 0,280 против 0,290 у ResNet18, holdout mAP 0,308 против
0,309. Поэтому внешний пилот пока не включён в основной Re-ID checkpoint.
Победа по классификации моделей сама по себе не означает улучшение поиска
конкретной машины.

Для отдельного экспериментального распознавания атрибутов есть интерфейс:

```python
from reid.infer import VehicleAttributeRecognizer

recognizer = VehicleAttributeRecognizer("outputs/external_pilot/best.pt")
labels = recognizer.predict(image_bytes, (x, y, w, h))
# {"make": {"label": "toyota", "score": ...}, "model": ..., "restyling": None}
```

`score` здесь softmax внутри собранных классов, не оценка правильности на
неизвестных марках. Для признака с менее чем двумя размеченными классами
возвращается `None`.

Пилотный checkpoint для атрибутов создан, но по восьми автомобилям нельзя
надёжно оценить обобщение на другие объявления. На известном Camry он уже
ошибался в марке и модели; использовать эти ответы в продукте рано.

## Ограничения текущей версии

- ResNet50 улучшила локальный протокол, но это не заявление о достигнутом качестве на скрытом тесте.
- В `data/auto_ru/raw/` сейчас 52 пробных снимка, из них одобрены 26. На части исходных снимков видны номера других машин, поэтому использовать всю папку raw в обучении нельзя. Внешний пилотный checkpoint есть, проверенной точности распознавания марки/модели/рестайлинга пока нет.
- Для демонстрации и сдачи все используемые веса нужно вложить в итоговый пакет. `data/` и `outputs/` игнорируются Git, чтобы случайно не отправить 7 ГБ изображений; итоговый checkpoint нужно добавить как согласованный отдельный артефакт.
- Порог отказа зависит от состава галереи. Перед сдачей стоит сравнить локальный протокол с эталонным скриптом организаторов.
