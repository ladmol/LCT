# Vehicle Re-ID без номера — ЛЦТ 2026, задача «Фалькон Тех»

Сервис строит цифровой признак (эмбеддинг) транспортного средства по кропу из кадра и ищет то же ТС в галерее снимков с других камер без использования государственного номера. Если уверенного совпадения нет, сервис возвращает отказ.

> **Статус:** репозиторий содержит ТЗ, данные организаторов и проектную документацию. Кода пока нет: реализация идёт по [`docs/dev-plan.md`](docs/dev-plan.md).

## Задача в двух словах

- **Open-set image retrieval.** Для каждого запроса из `test_query.csv` нужно упорядочить `test_gallery.csv` по вероятности, что это то же ТС. Автомобили теста в train не встречаются.
- **Bbox дан.** Детекция, распознавание номеров и трекинг в задачу не входят. Номера на кадрах размыты, а использование признаков номера ведёт к дисквалификации.
- **Сдача:** `submission.csv` (top-10), `embeddings.npy`, `candidates.csv` (кандидаты с уверенностью или отказ), а также код, Dockerfile и `docker-compose.yml`. Организаторы сами запускают решение на закрытой части теста, без интернета.
- **Оценка:**

  | Критерий | Вес |
  |---|---|
  | mAP (кросс-камерно) | 45% |
  | Скорость и веса ≤ 2 ГБ | 20% |
  | Инженерия | 15% |
  | Режим отказа (F1/TNR) | 10% |
  | Защита | 10% |

## Данные

`data/specs/` — данные организаторов:

- `train.csv` — 9 556 кадров, 1 541 ТС, 96 камер;
- `test_query.csv` — 1 110 кадров;
- `test_gallery.csv` — 750 кадров.

Каталог изображений `data/specs/images/` (≈7 ГБ) в git не хранится: его нужно распаковать туда из архива организаторов.

`data/raw/` (внешние датасеты) и `data/weights/` (веса) — только локально, в `.gitignore`.

Все используемые предобученные веса, открытые датасеты и библиотеки с версиями будут перечислены здесь по мере подключения (требование ТЗ §7).
