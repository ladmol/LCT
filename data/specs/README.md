# Сервис формирования цифрового признака ТС — датасет

## Состав

dataset/
images/ все изображения, плоский каталог, JPEG
train.csv image_id, x, y, w, h, vehicle_id
test_query.csv image_id, x, y, w, h
test_gallery.csv image_id, x, y, w, h


## Формат аннотаций

Один кадр — одно размеченное транспортное средство.

`x, y, w, h` — координаты ограничивающего прямоугольника ТС в пикселях
исходного кадра (левый верхний угол, ширина, высота).

`vehicle_id` — целочисленный идентификатор идентичности, присутствует
только в `train.csv`. Множества `vehicle_id` в train и test не пересекаются.

## Постановка задачи

Для каждого объекта `test_query.csv` необходимо упорядочить объекты
`test_gallery.csv` по убыванию вероятности принадлежности тому же ТС.

## Анонимизация

Государственные регистрационные знаки и лица людей в кадре размыты.
Использование любых остаточных признаков номерного знака для решения
задачи запрещено - решения, построенные на таких признаках, не
допускаются к итоговой оценке.

## Как сдавать решение

Проверка решений проводится организаторами вручную по завершении хакатона.
Автоматического лидерборда во время хакатона нет.

### Артефакты в репозитории

1. **submission.csv** — для каждого query первые 10 кандидатов из gallery
   по убыванию близости:

query_id, gallery_id_1, gallery_id_2, ..., gallery_id_10


2. **embeddings.npy** — векторы всех объектов тестовой выборки, порядок:
   сначала все `image_id` из `test_query.csv` (по порядку файла), затем
   все `image_id` из `test_gallery.csv`. Организаторы используют этот файл
   для проверки, что submission.csv получен реальной моделью, а не составлен
   вручную.

3. **candidates.csv** — результат режима предложения кандидатов: для
   каждого query — список принятых кандидатов с оценкой уверенности,
   либо пустой ответ (отказ):

query_id, gallery_id, confidence

   Порог отсечения выбирается командой самостоятельно и обосновывается
   в README решения.

4. **Код и окружение** — исходный код обучения и инференса, `Dockerfile`,
   `docker-compose.yml`, файл зависимостей. Инференс запускается одной
   командой в изолированном окружении, без доступа в интернет (все веса
   — в составе решения).

## Производительность

Финальные замеры проводит организатор на едином оборудовании после
хакатона, стандартизированным скриптом. Собственные замеры
скорости в отчёте участника носят справочный характер и не влияют на баллы.

- Время формирования признака на одно ТС, батч=1.
- Пропускная способность (FPS) при пакетной обработке, без деградации
  памяти и очередей.
- Суммарный размер весов — не более 2 ГБ.
- Инференс не должен приводить к Out-of-Memory на тестовой выборке.

## Внешние ресурсы

Использование публичных предобученных весов и открытых датасетов
разрешено и приветствуется. Все источники перечисляются в README решения.
Решения на закрытых, проприетарных или невоспроизводимых данных к оценке
не допускаются.
